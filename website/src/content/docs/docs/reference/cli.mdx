| Command | Does |
|---|---|
| `hull init` | Detects Dockerfile, vLLM or TGI; writes `multihull.yaml` |
| `hull doctor` | Checks credentials, quota and GPU availability per target |
| `hull plan` | Renders native payloads to `.multihull/plan/`, shows diff against state |
| `hull deploy` | Applies all targets concurrently, waits for ready, publishes a snapshot |
| `hull status` | Per-target phase, replicas, GPU and endpoint URL |
| `hull logs -p <provider>` | Streams logs from one target |
| `hull failover test -p <provider>` | Drains a target for 60 s; reports traffic shift, error count, sessions rehomed |
| `hull destroy` | Removes all targets; no-op for anything already gone |
| `hull schema` | Prints the JSON Schema for `multihull.yaml` |
| `hull controller` | Long-running reconcile loop and snapshot stream |

## Python SDK

```python
from multihull import Service, target

svc = Service.from_yaml("multihull.yaml")
svc.targets.append(target.modal("modal-eu", priority=2, region="eu"))
plan = svc.plan()
svc.deploy()
```

## State

Default backend is SQLite under `.multihull/`. Teams use `s3://`, `gs://` or `postgres://` URLs. Records hold `{service, provider, ref, imageDigest, specHash, lastStatus, updatedAt}`. A lost backend is recoverable: every resource is tagged `multihull.dev/service=<name>` and `hull` can rediscover it.
