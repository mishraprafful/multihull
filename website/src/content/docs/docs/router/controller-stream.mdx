---
title: Controller stream
description: Serve the hull controller's discovery stream over TLS with client certificates and a bootstrap token.
---

`hull controller` reconciles the targets and streams endpoint snapshots to routers over gRPC; routers send `Degraded` signals back. Snapshots can carry provider credentials such as Modal proxy tokens, so the stream is encrypted and authenticated unless you opt out.

## Controller

```sh
# MULTIHULL_DISCOVERY_TOKEN set from your secret manager
hull controller multihull.yaml \
  --grpc-listen 0.0.0.0:7700 \
  --tls-cert /etc/multihull/discovery/controller.crt \
  --tls-key /etc/multihull/discovery/controller.key \
  --client-ca /etc/multihull/discovery/ca.crt
```

| Flag | Effect |
|---|---|
| `--tls-cert`, `--tls-key` | PEM certificate chain and key the stream serves |
| `--client-ca` | Require router client certificates signed by this CA (mTLS) |
| `--token-env` | Env var holding the bootstrap token, default `MULTIHULL_DISCOVERY_TOKEN` |
| `--insecure` | Plaintext, local development only; logs a warning |

- Without `--tls-cert` and `--tls-key`, and without `--insecure`, the controller refuses to start.
- TLS needs client certificates, the token or both. Both is the recommended setup.
- With the token set, every stream must send `authorization: Bearer <token>`. A missing or wrong token gets `UNAUTHENTICATED` and a log line naming the peer, never the token.
- Certificates load at startup. Restart the controller to rotate them.

## Router

```toml title="router.toml"
[snapshot]
source = "grpcs://multihull-controller:7700"
ca = "/etc/multihull/discovery/ca.crt"
client_cert = "/etc/multihull/discovery/router.crt"
client_key = "/etc/multihull/discovery/router.key"
token_env = "MULTIHULL_DISCOVERY_TOKEN"
```

- `ca` replaces the public webpki roots for this source. Leave it out only when the controller's certificate comes from a public CA.
- `client_cert` and `client_key` go together. The router certificate needs the `clientAuth` extended key usage; the controller certificate needs a SAN matching the host in `source`.
- `token_env` names the variable; the router reads it at startup and fails to start if it is unset or empty.
- An `https://` snapshot URL takes the same keys and sends the same bearer token.
- A snapshot file needs none of them, but keep it at mode `0600` when it carries credentials.

## Local development

```sh
hull controller multihull.yaml --grpc-listen 127.0.0.1:7700 --insecure
```

```toml title="router.toml"
[snapshot]
source = "grpc://127.0.0.1:7700"
insecure = true
```

Plaintext `grpc://` and `http://` sources start only with `insecure = true`. It never turns off certificate checks on a TLS source.
