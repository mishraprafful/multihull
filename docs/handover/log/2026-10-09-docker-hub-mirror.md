# 2026-10-09 Docker Hub mirror (branch `ci/docker-hub-mirror`, issue 139)

- PR 138's CI got `429 Too Many Requests` from `registry-1.docker.io` in e2e, demo, kind, in-cluster and the three image builds. Docker Hub (docs read 2026-10-09): 100 pulls per 6 h per IPv4 address or IPv6 /64 unauthenticated, 200 for a free account, unlimited for paid plans. GitHub-hosted runners share addresses.
- Chosen: mirrors, not `docker/login-action`. `public.ecr.aws/docker/library/<image>` carries every Docker official image including old digests (ECR Public: 500 GB per month and 1 pull per second unauthenticated); `mirror.gcr.io` serves any public Hub image without login and lists no quota, and it is the only one with `kindest/node` (ECR Public answers `not found`). Digests are content addresses, so the same digest resolved on Hub, ECR Public and mirror.gcr.io (`docker buildx imagetools inspect` on each).
- Pinned: `python:3.12.15-slim-trixie@sha256:05cda977...` (already the controller's digest, now the mock server's too), `rust:1.99.0-slim-bookworm@sha256:2c3a22f0...` (the `rust:1-slim-bookworm` the router built with), `gcr.io/distroless/cc-debian12:nonroot@sha256:9dac0a79...`, `kindest/node:v1.37.0@sha256:a1ed56cf...` (kind v0.33.0's default, the version `helm/kind-action@v1.15.1` installs) in `testing/live/kind-config.yaml` and the new `testing/live/kind-in-cluster-config.yaml` (`make kind-in-cluster-up`).
- Trap: kind v0.30.0 with that node image fails `kubeadm init` ("old API spec kubeadm.k8s.io/v1beta3"); kind v0.33.0 creates it fine. Local kind must be at least the release the image was built for.
