# 2026-10-26 Credential overrides (issue 67)

- Branch `feat/credential-overrides`, PR 174. One resolver, `python/multihull/credentials.py`; translators get the target's `credentials` reference through their constructor (`engine.credential_kwargs`). RunPod, Baseten, Replicate and Docker read it on every call, so a rotated env var or file applies at once. Kubernetes builds its client at construction and Modal caches its client, so `hull controller` needs a restart to pick up a rotated kubeconfig or Modal token.
- The ref stores the reference (`ids["credentials"]`, never the value) so `destroy` and `refresh` of a target removed from the spec use it (`engine.provider_for_ref`); without it they ran against the native cluster or workspace and reported success.
- Formats are the providers' own: API key for RunPod, Baseten and Replicate; kubeconfig YAML (a `file:` source goes to `new_client_from_config` so relative cert paths keep working, an `env:` source to `new_client_from_config_dict`); `.modal.toml` profile tables picked as Modal 1.6 does (active, else the only one or `default`; token profiles only); Docker `config.json`, with an empty `auth_config` for a registry it lacks so docker-py never falls back to `~/.docker/config.json`.
- Router side unchanged: RunPod traffic uses the target's override key when it has one, else `RUNPOD_ENDPOINT_API_KEY`, else `RUNPOD_API_KEY`, in `inject_headers`. Modal proxy tokens are traffic credentials and are not overridden.
- Traps: `modal.Client.from_env` caches one client per process; pydantic's `hide_input_in_errors` is ignored on nested models; docker-py's `containers.run` auto-pulls a missing image with the native config. Parse errors of an override name only its source, since PyYAML's messages quote the offending line.
- Baseten and Replicate were render-only on `main`: only `credentials_health` and the constructor are wired. Their `apply` (issues 64, 65) reads the key with `read_token(self.credentials, API_KEY_ENV)`.
