- Decision: a separate `make demo-cloud` target, not `make demo DEMO_TARGET=cloud`. The cloud demo lives in the live harness project (`testing/live`, Python 3.12, `multihull[modal]`, `e2e` on `PYTHONPATH`), while `make demo` runs from `python/` with only the `demo` extra.
- Decision: the GPU variant is two Modal L4 targets, not kind plus a Modal GPU. A spec runs one image on every target and kind has no GPUs, so the vLLM image cannot also serve the kind leg. kind stays in the CPU variant.
- Decision: cloud demo services are `live-demo-<id>` so their Modal apps carry the `multihull-live-` prefix the sweeper refuses to work without; the per-run sweep and the daily sweeper both cover them.
